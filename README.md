一個不用架伺服器、開檔案就能用的排程時間軸表，用 HTML＋內嵌 XML 當資料庫，畫面用 JavaScript 讀 XML、畫成一格一格的時間軸。
一、畫面顯示
標題：線上專案進度時間軸表 / 副標「呼吸照護病房病房助理工作流程」
橫軸時間軸：當日07:00 → 當日23:59 → 翌日00:00 → 翌日23:59，每10分鐘一格，整點顯示「當日/翌日」
縱軸班別：固定順序 D白班 → E小夜班 → N大夜班 → T教學班 → L洗澡班，各有專屬顏色；左側同時列出該班別所有項目（依代號排序）
凍結窗格：時間軸列（頂）＋班別/項目欄（左）都固定，上下左右捲動時標題不會跑掉
色塊：只顯示兩位數代號，滑鼠停留看得到完整項目名稱
現在時間線：紅色虛線標示目前時刻
二、點選項目後的說明面板
顯示：班別、代號+項目名稱、開始/結束時間、時間內說明（放大50%字級、只能垂直捲動）
若有設定「輔助說明連結」，會顯示可點擊的網址
按鈕：編輯、刪除、◀上一筆／下一筆▶（依班別＋代號順序連續瀏覽）
三、資料編輯方式（三種）
新增/編輯項目（單筆表單）：班別（可新增班別，自動配色排序）、代號（兩位數字）、項目名稱、開始/結束（當日或翌日＋時間）、時間內說明、輔助說明連結（選填，會自動補 https://）
資料表檢視／編輯（整批表格）：欄位對照 班別/代號/項目名稱/開始/結束/說明/輔助連結；表頭列＋「項目名稱」欄凍結；每列可單獨按「儲存」即時存檔，也可整批「儲存全部」
匯入 XML：選檔或貼上文字，同班別內「項目名稱」相同就覆蓋，不同就新增，班別不存在就自動建立

另外還有「匯出備份（XML）」可以把目前資料複製起來另存。

四、資料庫（Firebase 即時同步）
資料存在你的 Firebase 專案（project-timeline-d2188）Firestore 的 shifts collection，一個班別一份文件
多裝置、多分頁打開會即時同步，不用手動整理
內嵌在檔案裡的 XML 只在 Firestore「完全空的」時當初始種子資料用，平常不會用到
有做「舊班別名稱自動改名＋排序修正」的一次性遷移機制
五、防止編輯被打斷的機制
編輯視窗（新增/編輯、資料表、匯入、匯出）開著時，雲端更新會先暫存，關閉視窗才套用
短時間內多次更新會合併成一次重畫，減少畫面閃動
資料內容完全沒變時直接跳過重畫
重畫後會保留原本的捲動位置與選取狀態
新增/編輯表單有草稿自動保存：內容會存在裝置本機，若異常中斷，下次打開會問你要不要復原（僅單筆表單，資料表批次編輯目前沒有這個保護，請養成常按「儲存」的習慣）
六、圖示
已內嵌 favicon（分頁小圖示）與「加入主畫面」用的圖示（時鐘造型，外圈五色對應五個班別）
⚠️ 使用上要注意的地方
正式使用請把檔案下載到裝置獨立打開（或加到主畫面），不要一直用跟我對話這裡的預覽畫面看，不然會一直因為我們對話而重新整理。
Firestore 安全性規則目前是完全開放（allow read, write: if true），任何人只要有這份程式碼裡的設定就能讀寫資料，僅適合內部/測試使用；要正式給多人長期使用，建議之後加上帳號登入權限控管。
需要網路連線才能連上 Firebase，離線會顯示連線失敗，且沒有離線快取機制。
一個班別是一份 Firestore 文件，如果兩個人在「完全同一瞬間」編輯同一個班別底下不同的項目，理論上有極小機率互相覆蓋（後存的為準）；不同班別之間不會互相影響。
代號沒有強制不重複檢查，同一班別內建議自己留意不要重複編號，避免時間軸上不好辨識。
手機瀏覽器背景太久被系統砍分頁重新載入，是作業系統層級行為，目前的草稿保護跟離開提示都無法百分之百防範這種情況。
